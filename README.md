# Последнее видео из @ptencoff

Страница показывает один ролик в стандартном видеоплеере. При сборке GitHub Actions ищет последнее видео в публичном превью и подставляет адрес видео из него. MP4 остаётся на стороне Telegram.

## Развёртывание

1. Загрузите файлы в корень репозитория, включая `.github/workflows/pages.yml`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. В **Actions → Telegram feed and GitHub Pages** нажмите **Run workflow**.
4. Адрес страницы появится в **Settings → Pages**.

Расписание проверяет канал в 17-ю и 47-ю минуты каждого часа. Если Telegram временно недоступен, сохраняется предыдущая версия сайта. Адрес файла может истечь. Очередная успешная сборка подставляет свежий адрес из превью.

## Локальная проверка

```bash
python3 build.py
python3 -m http.server 8766 --bind 127.0.0.1 --directory site
```

Откройте [страницу](http://127.0.0.1:8766/).

## Автопубликация в закрытый Telegram-канал

1. Создайте отдельного бота через [@BotFather](https://t.me/BotFather) и добавьте его в канал администратором с правом публиковать сообщения.
2. В GitHub откройте **Settings → Secrets and variables → Actions**. Добавьте секрет `TELEGRAM_BOT_TOKEN` с токеном бота. В `TELEGRAM_CHAT_ID` добавьте числовой ID канала. Например, для ссылки на сообщение вида `https://t.me/c/1234567890/7` ID канала будет `-1001234567890`.
3. Для первой публикации откройте **Actions → Publish video to Telegram → Run workflow** с режимом `publish`. Далее GitHub проверяет канал в 23-ю и 53-ю минуты каждого часа.

В канал отправляется последнее доступное MP4 до 50 МБ с подписью «Видос топ, а актуальное ниже» и до пяти хэштегов из Trends24 по России. Если источник недоступен, подпись сокращается до «Видос топ». Режим `preview_caption` показывает готовую подпись в журнале GitHub Actions. Ветка `telegram-publish-state` хранит номер последней публикации. Если Telegram не подтвердил отправку, проверьте канал перед повтором. Выберите `confirm_sent`, если видео появилось, или `clear_pending`, если его нет. Следующий запуск снова проверит последнее видео.
