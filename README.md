# Последнее видео из @voinaga

Страница показывает один ролик в стандартном видеоплеере. При сборке GitHub Actions ищет последнее видео в публичном превью и подставляет адрес видео из него. MP4 остаётся на стороне Telegram.

## Развёртывание

1. Загрузите файлы в корень репозитория, включая `.github/workflows/pages.yml`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. В **Actions → Telegram feed and GitHub Pages** нажмите **Run workflow**.
4. Адрес страницы появится в **Settings → Pages**.

Расписание проверяет канал в 17-ю и 47-ю минуты каждого часа. Если Telegram временно недоступен, сохраняется предыдущая версия сайта. Адрес файла может истечь. Очередная успешная сборка подставляет свежий адрес из превью.

## Локальная проверка

```bash
python3 build.py
python3 -m http.server 8766 --bind 127.0.0.1 --directory site
```

Откройте [страницу](http://127.0.0.1:8766/).

## Автопубликация в закрытый Telegram-канал

1. Создайте отдельного бота через [@BotFather](https://t.me/BotFather) и добавьте его в канал администратором с правом публиковать сообщения.
2. В GitHub откройте **Settings → Secrets and variables → Actions**. Добавьте секрет `TELEGRAM_BOT_TOKEN` с токеном бота. В `TELEGRAM_CHAT_ID` добавьте числовой ID канала. Например, для ссылки на сообщение вида `https://t.me/c/1234567890/7` ID канала будет `-1001234567890`.
3. Для первой публикации откройте **Actions → Publish video to Telegram → Run workflow** с режимом `publish`. Далее GitHub проверяет канал каждые два часа, в 23-ю минуту чётного часа UTC.

В канал отправляется последнее доступное MP4 до 50 МБ с подписью «Видос топ, а актуальное ниже» и до пяти хэштегов из Trends24 по России. Если тегов меньше пяти, недостающие позиции заполняются хэштегами из поисковых тем Google Trends по России. Если оба источника недоступны, подпись сокращается до «Видос топ». Режим `preview_caption` показывает готовую подпись в журнале GitHub Actions. Ветка `telegram-publish-state-voinaga` хранит номер последней публикации из @voinaga. Если Telegram не подтвердил отправку, проверьте канал перед повтором. Выберите `confirm_sent`, если видео появилось, или `clear_pending`, если его нет. Следующий запуск снова проверит последнее видео.

## Тестовая загрузка на YouTube

В Google Cloud включите YouTube Data API v3 и создайте OAuth-клиент для настольного приложения. При входе в @Filkina_Gramata выдайте разрешения `youtube.upload` и `youtube.readonly` и запросите офлайн-доступ. Храните ID клиента, секрет клиента и refresh token в секретах GitHub `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET` и `YOUTUBE_REFRESH_TOKEN`. При статусе OAuth-приложения Testing токен внешнего пользователя обычно истекает через семь дней.

Запускайте **Publish video to YouTube → Run workflow** с номером ролика, который сейчас отображается на GitHub Pages. Выберите режим доступа к видео. Перед загрузкой проверяется ID канала, после неё проверяется выбранный режим. YouTube проверяет GitHub Pages каждые два часа, в 23-ю минуту чётного часа UTC. Новый ролик публикуется сразу без хэштегов. Состояние хранится отдельно в ветке `youtube-publish-state-voinaga`. Если результат отправки неизвестен, проверьте YouTube Studio и запустите `confirm_sent` или `clear_pending` перед повтором.
